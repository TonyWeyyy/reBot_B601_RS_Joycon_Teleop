# AGENTS.md

## What this is
- Python (not Rust, despite the `-rs` suffix) teleoperation project for the Seeed reBot Arm B601-RS with RobStride motors over SocketCAN.
- User-facing entrypoints are the numbered scripts in `examples/`; shared control logic lives in `rebot_joycon/`. `config/default.yaml` is the source of truth for paths, safety limits, HOME, and logging.
- `joycon-robotics/` is a vendored third-party checkout installed editable by `install.sh`; don't modify it for project fixes.

## Setup and verification
- `bash install.sh` uses the active conda env, otherwise creates `.venv` with Python 3.12 (falls back to `python3` 3.10+), installs deps and the vendored Joy-Con package, then runs the test suite.
- SDKs are external. `arm.rebot_sdk_path` / `arm.sdk_path` in `config/default.yaml` point at local `rebot*` and `reBotArm_control_py` packages; the checked-in paths are machine-specific. `Settings.load()` fails fast if the URDF or hardware YAML is missing.
- LeRobot requires separate install and `PYTHONPATH` setup; follow `learning/README.md`.
- Full hardware-free suite: `python3 tools/smoke_test.py` (57 unittest tests). The README uses `python`; this shell only has `python3`.
- Single test: `python3 -m unittest tests.test_project.ProjectTests.test_03_soft_limits`
- No lint, typecheck, formatter, codegen, or CI config exists. The smoke tests are the verification source of truth.

## Running
- Every example funnels through `examples/_common.py` into `rebot_joycon/cli.py`. Key flags: `--mode qpos|gpos`, `--input keyboard|joycon`, `--real`, `--dry-run`, `--backend auto|mit|pos_vel`, `--max-vel`, `--headless`, `--duration`, `--yes`.
- Defaults are safe for development: FakeBackend unless `--real`; `--dry-run` keeps the fake arm but real input. `--real` prompts for uppercase `RS` unless `--yes`.
- CAN is not persistent: rerun `bash tools/setup_can.sh can0` (sudo, 1 Mbps) after reboot or PCAN replug.
- Motion requires holding Space (keyboard) or R (Joy-Con); release or estop (`R + R-Stick`) triggers safety stop. Right Joy-Con uses Scheme A via the native single-handle `hidraw` driver (`rebot_joycon/joycon_driver.py`): `R` = deadman clutch, Stick = world X/Y, `X`/`B` = pure +Z/-Z, `ZR` = gripper toggle (only while holding `R`), `+` (`plus`) = HOME, long-press `Home` (0.6s) = safe exit, `A`/`Y` = LeRobot episode control. `--home-on-start` is opt-in; normally the arm holds its current pose. It sets `home_pending`, which survives the startup guard and deadman waits: the first actual deadman hold starts homing (releasing mid-home pauses it). Once HOME is reached the gate latches, so release and re-hold before teleoperating. The controller prints throttled `[等待]` reasons and HOME progress and writes structured telemetry/error events into `logs/`.
- Run events are JSONL files under `logs/`.

## Invariants and gotchas
- MuJoCo view uses `simulation.urdf` when it exists (currently a machine-specific RS digital-twin MJCF with mesh/light/table), then the official SDK full URDF, then the colored lightweight URDF. This only affects rendering, not kinematics or limits.
- Core control uses radians and a 7-element vector (6 joints + gripper) ordered `shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_yaw, wrist_roll, gripper`. Only the LeRobot boundary converts to degrees.
- Never disable torque or power off in a bent pose. All stops must go through `safe_stop()`: smooth return-to-zero, wait for feedback, then disable. Don't bypass or replace this path. Sole exception: a second Ctrl+C during MIT homing is an explicit abort, so `safe_stop()` catches it and calls the SDK `stop(return_to_zero=False)` to genuinely disable before exiting, instead of leaving motors enabled.
- `JointLimiter.validate()` allows a uniform 1° feedback tolerance on all seven channels: the RS all-zero folded pose sits exactly on the J2/J3 lower limits, so post-homing encoder drift of about -0.1° must not block restart (previously only the gripper had this tolerance). Command targets are still strictly clamped to the soft limits. Do not widen the tolerance beyond 1°; larger deviations require the official recovery tool and zero calibration check.
- `Settings.validate()` enforces safety bounds: `joint_limit_scale <= 0.7`, `workspace_radius_m <= 0.62` (centered at shoulder `(0, 0, 0.145)`, ~70% of RS real reach), `input_watchdog_s <= 0.5`, and `--max-vel` within 0.005–1.0 rad/s. Don't loosen these defaults.
- `RSKinematics.ik()` solves directly inside `JointLimiter.soft[:, :6]` with direction-preserving step scaling, and `JointRateLimiter` scales the 6 arm joints proportionally so pure Cartesian translation stays straight without joint-saturation drift.
- Native single-handle Joy-Con driver (`rebot_joycon/joycon_driver.py`) uses `hidraw` (with `hid` fallback), strictly matches right PID `0x2007` (never substitutes left), performs 1.2s stationary gyro/stick center calibration, runs an SO(3) quaternion complementary filter (`QuaternionAttitudeFilter`), and drives `TeleopController` via relative clutch anchors + velocity/SO(3) targets (don't edit `joycon-robotics/`). Keyboard uses listener-thread liveness (`streaming_heartbeat=False`) so holding Space does not trip the 0.25s streaming watchdog.
- `auto` backend prefers MIT and falls back to POS_VEL. MIT SDK calls use degrees; the loader accepts `rebot_control`, `rebot`, and `rebot.robot` layouts. The current SDK exposes only `read_joint_angles()` and `last_temperatures`; its per-frame position read does 7 CAN parameter requests and can exceed the 250 ms loop-stall guard. The MIT backend therefore prefers the `controller.motors[*].get_state()` motorbridge cache for position/velocity/torque (no extra CAN traffic), waits up to 2 s at connect for the first gripper-torque frame, and validates cached positions against one exact SDK read at connect (>2° mismatch or missing cache falls back to the slow SDK path). Keep strict torque feedback enabled. After the project's own return-to-zero converges, it calls SDK `stop(return_to_zero=False)` so the SDK does not home a second time.
- A `~/.local` Pinocchio can shadow the conda env and break POS_VEL/gravity compensation with an `undefined symbol` error. `backends.py` now prioritizes the active env `site-packages` before importing that SDK; if it still fails, use `PYTHONNOUSERSITE=1` or a compatible env-local `pinocchio`.
- On some RS firmware `motorbridge` never fills its feedback cache, so `PosVelBackend` falls back to `robstride_get_param_f32(0x7019)` for positions. Velocity/torque/temperature are then unavailable; use MIT when those protections matter.
- Joy-Con input prefers the Linux `hidraw` module over pyhidapi (which needs system `libhidapi`), runtime-patches the vendor serial-prefix checks, replaces the vendor's `sin(heading)` yaw with a continuous unwrapped heading, and writes orientation-limit overflow back to the offset to prevent windup. Don't edit `joycon-robotics/` for these. The IMU watchdog heartbeat comes from a `gyro.register_update_hook()` callback on real hidraw input reports (stationary controllers still stream packets); evdev IMU change events are only a fallback, since evdev can go quiet when values do not change.
- `config/default.yaml` `joycon.imu_*` controls yaw scale, gyro deadband, roll/pitch low-pass alpha, and SO(3) target rate. Defaults are conservative; don't disable the rate limit or widen orientation limits to mask hardware/IMU issues.
- `config/calibration_snapshot.json` is read-only feedback, not motor-zero offsets. The default URDF is the simplified model; the full `ReBot_Arm_RS.urdf` is the authority for joints/limits.
- MIT read-only snapshots are rejected because this SDK enables motors before feedback is readable; use POS_VEL for unenabled snapshots. Strict mode requires gripper torque and, after a grace period, temperature feedback. Hardware timestamp enforcement is available but remains opt-in for SDK compatibility.
- Motion, gripper, Joy-Con, gravity compensation, and LeRobot hardware flows are unverified in this delivery. The 51 hardware-free tests are not a real-arm safety certification; use FakeBackend/`--dry-run` before staged low-speed validation.
